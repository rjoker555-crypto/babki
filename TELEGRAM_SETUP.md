# Telegram VoltMaster: безопасный запуск

Серверные таблицы и функции подготовлены. Бот не считается запущенным, пока владелец не внесёт секреты, не зарегистрирует webhook и не проверит доставку в настоящем личном чате. Публичный адрес frontend пока не опубликован.

1. В [BotFather](https://t.me/BotFather) создайте отдельного бота и запишите его `@username`. Отключите групповое использование бота (Allow Groups — Off). Код всё равно принимает только `private` и сверяет `from.id` с `chat.id`.
2. В Supabase Dashboard проекта `tkoxgvftneoereukiomr` откройте **Edge Functions → Secrets**. Введите там, не в Git, SQL, чате и frontend:
   - `TELEGRAM_BOT_TOKEN` — токен BotFather;
   - `TELEGRAM_BOT_USERNAME` — username без `@`;
   - `TELEGRAM_WEBHOOK_SECRET` — собственная случайная строка из 32–128 символов `[A-Za-z0-9_-]`;
   - `TELEGRAM_INTERNAL_SECRET` — *другая* случайная строка не короче 32 символов;
   - `VOLTMASTER_APP_URL` — HTTPS-адрес приложения после публикации (необязателен для запуска);
   - существующий `OPENAI_API_KEY` нужен только для модели и распознавания голоса. Общие серверные `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` остаются штатными секретами Supabase.
3. Для регистрации webhook войдите в опубликованное приложение директором с допуском, откройте «Telegram» и нажмите «Зарегистрировать webhook». Кнопка обращается к защищённой функции `telegram-admin`, которая вызывает `setWebhook` сервером; токен в браузер не возвращается. «Проверить webhook» вызывает `getWebhookInfo` и показывает адрес, число ожидающих событий и дату последней ошибки. Адрес webhook: `https://tkoxgvftneoereukiomr.supabase.co/functions/v1/telegram-webhook`. Он принимает запрос без Supabase JWT **только** с `X-Telegram-Bot-Api-Secret-Token`.
4. Для гарантированных повторов после сбоев и очистки временного хранилища настройте ежеминутный вызов `telegram-worker` по [Supabase Cron](https://supabase.com/docs/guides/functions/schedule-functions). Образец без значений секретов: [worker-cron.sql](docs/telegram/worker-cron.sql). Секреты для cron внесите отдельно через **Supabase Vault** с именами `telegram_worker_service_role_key` и `telegram_worker_internal_secret`; значения должны совпадать соответственно с серверными `SUPABASE_SERVICE_ROLE_KEY` и `TELEGRAM_INTERNAL_SECRET`. Проверьте доступ к Vault и только затем примените образец в SQL Editor. Это дополнительный защищённый вызов: обработчик всё равно требует валидный service JWT и внутренний заголовок. Без cron первое событие будит worker, но очередь после сбоя может ждать следующего сообщения.
5. Директор и прораб отдельно входят в приложение и нажимают «Подключить Telegram». Одноразовая ссылка действует 10 минут; её открывают в личном чате с ботом. Только активный директор с допуском к агенту или активный прораб могут привязаться. При отзыве роли/назначения/аккаунта доступ перепроверяется. Для прораба назначьте объекты в карточке объекта прежде, чем выбирать их в боте.
6. Проверка запуска на тестовых аккаунтах: директор — новый чат, консультация, указание с кнопкой подтверждения, загрузка двух файлов в один объект; прораб — подача файла и пояснения, просмотр статуса, отказ в команде и чужом объекте; директор — принятие входящего файла в документы. Затем проверьте голосовое сообщение Telegram OGG/Opus и отражение истории в приложении. Эта живая проверка пока не выполнена. Вызовы модели и распознавания расходуют общий лимит приложения; отдельного разрешения на платный тест в этом задании нет.
7. Для остановки нажмите «Отключить webhook» в панели директора, затем отключите привязки аккаунтов. При компрометации токена перевыпустите его в BotFather и обновите Edge Function Secret; при компрометации webhook/internal secret замените их и перерегистрируйте webhook. Кнопка отключения привязки прекращает доступ данного аккаунта сразу. Очистка файлов временной подачи выполняется после семи суток при работающем worker; срок хранения переписки в приложении не удаляет сообщения из Telegram.

Ограничения файлов: до 8 МБ, не больше пяти файлов в одной подаче; PDF, DOCX, XLSX, TXT, JPEG, PNG. Голос до трёх минут и 3 МБ. Загрузка и хранение файла не означают, что агент умеет редактировать его содержимое или полностью анализировать формат. Для замены документа директор готовит новый файл; предметная команда сохраняет прежнюю версию после отдельного подтверждения.
