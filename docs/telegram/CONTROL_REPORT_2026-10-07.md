# Контроль реализации Telegram VoltMaster — 07.10.2026

Статус: **серверная основа развёрнута, запуск бота не подтверждён**. Публичный frontend не менялся по действующему ограничению рабочего чата. Настройка secrets, регистрация webhook, cron и живое испытание Telegram остаются за владельцем/следующим этапом. Никакого имени бота или адреса опубликованного frontend в доступных данных не подтверждено.

| Действие из ТЗ | Реализовано | Проверено |

| Директор: консультация без записи | Запрет записи/подтверждения в общем агенте | Локальный код; реальный модельный ответ не испытан |

Развёрнуто в Supabase `tkoxgvftneoereukiomr`: `main-agent` v20 (JWT), `telegram-link` v1 (JWT), `telegram-webhook` v1 (обязательный собственный секрет), `telegram-worker` v4 (JWT + внутренний секрет), `telegram-admin` v1 (JWT), `telegram-review` v1 (JWT), 12 добавочных SQL-миграций. Существующие `agent-files` и прочие службы не ослаблялись. Исходники frontend и панели подачи подготовлены **только локально**.

Проверки: три изолированных SQL-сценария [telegram-bridge.sql](../../tests/telegram-bridge.sql), [telegram-submission.sql](../../tests/telegram-submission.sql), [telegram-director-batch.sql](../../tests/telegram-director-batch.sql) прошли повторно с откатом тестовых строк. [telegram-core.test.cjs](../../tests/telegram-core.test.cjs) и [frontend-compatibility.cjs](../../tests/frontend-compatibility.cjs) прошли; `node --check` новых UI/Edge-файлов прошёл. Попытка полного произвольного прогона `tests/*.cjs` остановилась на отсутствующем локальном `jszip` в старом `agent-document-flow.test.cjs`; это не считается пройденным полным набором. Прямой HTTP smoke из песочницы заблокирован сетевыми правами, список Edge Functions подтвердил активные версии.

Расход OpenAI API в этой задаче: **$0, вызовов модели/распознавания не запускалось**. Стоимость реального теста и поведение OGG на настоящем файле пока неизвестны. Общий лимит вызовов в приложении подключён к Telegram, однако живое расходование не проверено.

Оставшиеся ограничения: секреты бота и его `@username` не предоставлены через безопасный серверный канал, поэтому webhook не зарегистрирован и реальные кнопки/документ/голос не испытаны; cron из [worker-cron.sql](worker-cron.sql) не включён без Vault secrets; frontend не опубликован. Файл, отправленный в режиме консультации, сейчас получает просьбу перейти к «Подать документ», то есть отдельное временное чтение такого файла ещё не готово. Для XLSX и изображений предусмотрены проверка и хранение, но извлечение содержимого главным агентом не заявляется. Статус фонового анализа доступен в приложении, а не в Telegram. Повтор при сбое распознавания после оплаченного вызова не должен незаметно запускать второй вызов; текст может потребовать повторной отправки пользователем.
