## Реализованные изменения

Финансы, долги и позиции получили общие атомарные команды с сохранением ручной базы оплаты/факта. Жизненный цикл кредита и отсроченных ТМЦ разделяет получение, себестоимость и движение денег. Карточка с позициями, работы с нормативами, разделы, шаблоны и подачи объёмов сохраняются согласованно. Добавлены предметные действия для сотрудников, постоянных расходов, событий, контактов, задач, существующих записей ПТО и КП.

Директор может назначить прораба и ответственного из карточки или чата и настроить существующий регламент. Отзыв назначения не скрывает объект, если пользователь остаётся ответственным: это прежняя разрешённая семантика, интерфейс предупреждает. Прораб создаёт базового субподрядчика через прежнюю специальную команду без финансовых полей.

Документы получили реальные загрузку, файл текущей/старой версии, прикрепление, замену и согласованное удаление. Старые версии сохраняют собственный Storage bucket. Общие и личные файлы сохраняются, остальные удаляются проверяемой очередью. Удаление целого объекта согласует полный перечень зависимостей, проверяет его ещё раз, атомарно удаляет записи и отдельно подтверждает очистку Storage. Изменившийся состав или сторонние финансовые связи останавливают удаление.

Для TXT создаётся настоящий файл новой редакции с точным количеством замен, хэшем и diff. Оригинал меняется только после отдельного подтверждения замены. Цена договора по ДС изменяется отдельным подтверждаемым шагом с историей; загрузка файла цену скрыто не меняет.

Отчёты вынесены в общий renderer. Агент выдаёт приватные HTML/TXT-файлы, проверяет байты/хэш и получает целостный снимок одним RPC. Исправлены подтверждённые несоответствия: двойной учёт налогов/отсроченной себестоимости, использование прежнего ручного факта вместо датированных записей, трактовка старого кредита без вида в месячном отчёте, включение получения отсроченных ТМЦ в денежный график. Управленческие ставки и финансовая методика сохранены.

## Ограничения и последующая приёмка

1. Автоматического редактора DOCX/PDF/XLSX с сохранением форматирования, подписей и печатей нет. Рабочий путь — загрузка готовой редакции и подтверждённая замена с версиями. Точная редакция доступна для UTF-8 TXT; алгоритм проверен по настоящим байтам, отдельного live Edge-вызова редактора не было.
2. Сервер выдаёт настоящие HTML/TXT. PDF получается через прежнюю печать/экспорт браузера. Нативной серверной конвертации PDF без отдельного движка нет; новые платные сервисы не подключались.
3. Вход/выход остаются штатным Auth/UI. Универсального редактора ролей нет; отдельного ручного редактора аккаунтов в текущем приложении не найдено. Назначения объектов директором реализованы отдельным проверенным инструментом.
4. Отчёт: полный снимок до 10 000 строк на таблицу, файл до 1,5 МБ, 20 отчётов на пользователя/день. Превышение останавливает формирование; неполный отчёт не выдаётся. Остатки долгов в месячном отчёте сохраняют прежнюю глобальную методику при фильтре компании; изменение этой методики не делалось.
5. Supabase Advisors сохраняет предупреждение об отключённой [проверке утёкших паролей](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection); она не активировалась в рамках задачи. Закрытые RLS-таблицы без клиентских policy и authenticated SECURITY DEFINER команды намеренны: доступ через предметные функции проверен ролевыми тестами.
6. Frontend готов локально, но публикация остаётся отдельным последующим шагом владельца. Старый опубликованный интерфейс не получает новые локальные формы автоматически.

## Запросы для пользовательского контроля

Использовать отдельный тестовый объект, финансовые планы читать до подтверждения.

- «Создай ЖК Ёлки на три миллиона на ИП, остальное заполню позже» — без выдуманных реквизитов.
- «Пришло пятьдесят тысяч по этому объекту» — местная дата, без произвольной дебиторки.
- «Покажи последнюю по дате и последнюю внесённую. В последней внесённой исправь только сумму на 13 тысяч».
- «Добавь ТМЦ с отсрочкой до [явная дата], покажи долг, себестоимость и денежный баланс».
- «Прикрепи этот проект к объекту»; «Замени документ этим файлом и покажи старую версию».
- «Назначь прораба [конкретный аккаунт] на этот объект» — проверить видимость под его входом.
- «Подай выполненные объёмы за [период]» — проверить состав/подтверждение, затем отчёт.
- «Сформируй выписку и месячный отчёт за октябрь 2026» — открыть реальный файл и сравнить с ручным интерфейсом после его публикации.

Для приёмки использовать эту матрицу и точные ограничения, а не прежний незавершённый отчёт первого этапа.
